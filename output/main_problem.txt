The system must use a tiered asset strategy.

The core rule
Index everything. Rig only what needs interaction.

Most assets never need internal animation.

A cloud does not need a rig.
A background tree does not need a rig.
A distant building does not need a rig.
A person carrying a bucket does need a rig.
A fire extinguisher spraying does need a rig.

5. What if the selected asset is not riggable?
The system should not force it.

It should evaluate the asset and choose one of four options:

Option A: Use it as-is
If the requested action does not require internal movement.

Option B: Use a simpler compatible asset
If another asset already has the required rig.

Option C: Build a rig for it
If the asset is valuable and reusable.

Option D: Rebuild a clean reusable version
If the original asset is too tangled or incompatible.

7. How do we avoid AI analyzing everything?
AI should be used selectively.

The indexer can handle the cheap, mechanical work:

scan files
read SVG structure
extract dimensions
extract groups
identify filename clues
calculate bounding boxes
group visual styles
AI is only called when:

the filename is ambiguous
the asset is requested for a scene
the asset needs semantic description
the asset may need rigging
the system needs to choose between similar assets
So AI operates on demand, not across the entire library.
