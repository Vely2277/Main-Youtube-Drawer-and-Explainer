Brooo 😂 This is a genuinely interesting direction. And unlike the heavy image-generation route, this architecture actually makes sense for your 8GB RAM, CPU-only laptop.

I especially like the separation of responsibilities:

* Python finds relevant visual assets.
* A small local model decides how to arrange them.
* Manim handles the actual drawing animation.
* FFmpeg assembles the video and audio.

That gives us something predictable and controllable instead of asking one AI model to generate an entire video.

But before we start coding, I want to correct a few expectations so we don’t build something that disappoints you.

The important corrections

There are four things we should be careful about:

1. SVGs aren’t automatically hand-drawn animations. Manim can animate SVG paths, but many illustration packs contain filled shapes rather than natural pen strokes. Create() can reveal their outlines, but that doesn’t necessarily look like someone drawing the illustration by hand. Manim Community v0.22.0 +1

2. The 5,000-SVG library is a target, not a guarantee. We need to inspect the actual downloadable packs and their contents before deciding how much material we have.

3. Qwen 2.5 3B is possible, but 8GB RAM is tight. Its Ollama download is approximately 1.9GB, before runtime memory and everything else running on Windows. Ollama +1

4. We don’t need FAISS or an LLM immediately. We can build a working prototype with a handful of SVGs and ordinary Python first. That will tell us whether the visual result is worth developing.

Here’s the build order I’d choose

* Phase 1 — Prove the drawing effect
    Load 3–5 SVG illustrations into Manim and animate their strokes. Export a short MP4.
    First priority
* Phase 2 — Build the visual library
    Collect and organize characters, buildings, vehicles, money, objects, backgrounds and expressions.
* Phase 3 — Add intelligent scene composition
    Introduce semantic search and the small local model to choose and position assets.
* Phase 4 — Automate production
    Connect narration, scene timing, transitions, subtitles and FFmpeg export.

Some good starting libraries:

* unDraw — useful for scenes and objects. Website⁠￼.

openpeeps.com +1

My decision: start with render_video.py

Not the indexer.

I want us to prove one thing first: Can your HP ProBook actually render a convincing drawing animation from an SVG without taking forever?

We’ll start with a simple scene: a person, a house and a tree being drawn onto a white background. Then we can judge the stroke quality, rendering speed and final appearance.

If that works, we have a foundation. If it doesn’t, there’s no point building a whole AI pipeline on top of it.

And one more thing: I want the eventual system to support recurring characters and visual consistency across scenes. That’s important if we’re going to make proper stories rather than disconnected collections of doodles.
